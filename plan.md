# plan.md

## 1. Objectives
- Создать **один** файл персоны `identity/personas/expert.md`, который **реально парсится OpenAkita** (v1.27.40) и обеспечивает строгий «экспертный» режим без воды/эмодзи/ложных утверждений.
- Доказать работоспособность через POC: скрипт, который повторяет **точные** регэкспы/логику парсера OpenAkita и валидирует файл (без моков).
- Собрать MVP веб-приложение (FastAPI + React) для просмотра/валидации/скачивания файла и превью того, **что LLM реально получает**.

## 2. Implementation Steps

### Phase 1 — Core POC (изоляция, не двигаться дальше пока не зелёное)
**User stories (POC):**
1. Как разработчик, я хочу прогнать скрипт и увидеть, какие секции OpenAkita реально извлёк из файла.
2. Как разработчик, я хочу увидеть извлечённые значения `正式程度/幽默感/回复长度/情感距离/表情使用` и их валидность по enum.
3. Как разработчик, я хочу получить превью итоговой prompt-вставки (аналог `get_persona_prompt_section()`), чтобы понимать, что попадёт в system prompt.
4. Как разработчик, я хочу, чтобы скрипт падал, если в файле есть emoji/пиктограммы или неверная кодировка.
5. Как разработчик, я хочу, чтобы скрипт падал, если ключевые секции пустые (иначе персона не работает).

**Шаги:**
1. (Web search) Быстро сверить best-practice детект emoji/Unicode pictographs в Python (regex ranges vs `unicodedata`, чтобы не словить ложные срабатывания).
2. Создать `/app/test_core.py` (или `scripts/test_core.py`):
   - Портировать из `src/openakita/agent/persona.py`:
     - `_parse_preset_field()` и правила секций: **только** `性格特征/沟通风格/提示词片段/表情包配置`.
     - `_parse_dimension_from_style()` с лейблами `正式程度/幽默感/回复长度/情感距离/表情使用`.
     - парс `使用频率`.
   - Добавить проверки:
     - все 4 секции не пустые;
     - значения измерений ровно: `neutral/none/short/professional/never` и входят в enum;
     - `使用频率 == never`;
     - файл UTF-8;
     - emoji/pictographic codepoints отсутствуют;
     - сгенерировать «prompt preview» (структурно как `get_persona_prompt_section()`), вывести в stdout.
3. Создать первоначальный `identity/personas/expert.md` (черновик) с **китайскими заголовками** (строго `## <NAME>` и ничего после на строке) и RU+EN содержимым внутри секций.
4. Гонять POC → фиксить файл, пока все assert’ы не пройдут.

### Phase 2 — V1 App Development (вокруг доказанного core)
**User stories (V1):**
1. Как пользователь, я хочу открыть страницу и увидеть полный текст персоны.
2. Как пользователь, я хочу нажать “Validate” и получить отчёт: какие секции найдены/пустые и какие значения стиля распарсились.
3. Как пользователь, я хочу увидеть панель “Что LLM реально получает” (prompt preview).
4. Как пользователь, я хочу скачать `.md` файл одним кликом.
5. Как пользователь, я хочу скопировать файл в буфер обмена без форматирования.

**Backend (FastAPI):**
1. Эндпоинты без моков:
   - `GET /api/persona/raw` → вернуть байты/текст `expert.md`.
   - `POST /api/persona/validate` → прогнать **тот же код**, что в POC, по реальному файлу и вернуть JSON: секции, parsed dims, enum validity, sticker freq, emoji scan, prompt preview, token estimate.
2. Хранение файла: единственный источник истины `identity/personas/expert.md` (читает с диска).

**Frontend (React SPA):**
1. Экран: три вкладки/панели:
   - “Persona file” (markdown viewer + код-блоки);
   - “Validation report” (таблица секций/значений/ошибок);
   - “LLM prompt preview” (моноширинный блок текста).
2. Кнопки: Validate, Copy, Download.
3. Текстовые инструкции установки (без эмодзи):
   - положить файл в `identity/personas/expert.md`;
   - включить `/persona expert` или `persona_name=expert`.

**Завершение фазы:**
- 1 прогон testing_agent_v3: загрузка страницы → Validate → Copy → Download.

### Phase 3 — Hardening (качество, без расширения скоупа)
**User stories (Hardening):**
1. Как пользователь, я хочу видеть понятные ошибки, если файла нет или он не UTF-8.
2. Как пользователь, я хочу видеть, какие конкретно секции пустые и почему это ломает движок.
3. Как пользователь, я хочу гарантировать, что в UI нет emoji/декоративных символов.
4. Как пользователь, я хочу, чтобы валидатор работал одинаково локально и в деплое.
5. Как пользователь, я хочу видеть стабильную оценку tokens и размер файла.

**Шаги:**
1. Добавить unit-тесты для валидатора (минимум: happy path, пустая секция, неверный enum, emoji найден).
2. Уточнить линтер «вода/хеджинг»: жёсткий список запрещённых шаблонов (RU) + отчёт с найденными совпадениями (fail).
3. Подчистить UI состояния: loading/error/empty.
4. Ещё 1 прогон testing_agent_v3.

### Phase 4 — (опционально, только по запросу) редактирование файла в UI
**User stories (Optional):**
1. Как пользователь, я хочу отредактировать файл в браузере и сразу увидеть валидность.
2. Как пользователь, я хочу сохранить изменения на сервер и скачать версию.
3. Как пользователь, я хочу видеть diff/подсветку изменений.
4. Как пользователь, я хочу автопроверку на emoji и неверные заголовки до сохранения.
5. Как пользователь, я хочу шаблон секций, чтобы не сломать парсер.

## 4. Success Criteria
- POC: `python /app/test_core.py` завершается с exit code 0 и печатает prompt preview.
- Валидатор подтверждает: 4/4 секции непустые, dims валидны, `使用频率=never`, emoji=0.
- В `提示词片段` присутствуют жёсткие правила: anti-hallucination, question-first (max 5), no-fluff, no-emoji, текстовые статус-маркеры, запрет смягчения правил memory/trait mining.
- V1 app: пользователь может просмотреть файл, провалидировать, скопировать и скачать; нет мок-данных; UI без emoji.
- E2E: testing_agent_v3 проходит основной поток без багов.
